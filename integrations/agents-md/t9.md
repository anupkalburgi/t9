## Project memory (t9)

This machine runs t9, a shared memory for coding work across sessions and agents, including each project's
decision log. Use the `t9` CLI (pass `--agent codex`, or your harness name, on writes):

- **First thing in every session**, run `t9 context` and continue from its "Last handoff" and "Current focus".
  Respect its "Decisions that apply", "Rules for every project" and "Ruled out" sections. If it says the
  folder is not linked to a t9 project, tell the user in your first reply and offer the suggested
  `t9 project init --name "…" --key …` (or `t9 project link KEY`); run it once they agree.
- **Before planning an approach or asking the user to choose**, run `t9 history "topic"` (decisions, rejected
  options, experiments and their outcomes, ideas, resources, oldest first). Follow decisions, don't repeat failed
  experiments unless what made them fail has changed, combine old ideas with what is known now, and cite ids.
- If the brief's About is not written yet, draft it from the README and record it once the user agrees
  (`t9 about set what "…"`, `t9 about add "…" --section stack|run|architecture|data`).
- Record experiments (`t9 add experiment "…" --hypothesis "…"`; outcome with `t9 done ID` or
  `t9 status ID failed|inconclusive -n "why" --retry-when "…"`) and resources you work with
  (`t9 add resource "…" --type dataset|table|model|endpoint|service|… --at LOCATION`). Never record credentials.
- **When the user decides or rules something out**, record it immediately:
  `t9 decide "…" --because "…" [-r "alternative: why not"] [--area A] [--for ID] [--global]`,
  `t9 reject "…" --because "…"`, or `t9 decide "…" -s OLD-ID` when changing an earlier decision.
- Starting a unit of work: `t9 focus ID` (shows the decisions that apply), or `t9 add task "…" [--parent ID] --focus`.
- After meaningful steps or findings: `t9 log "…"` (one or two specific sentences; `-r path` for evidence).
- Bugs, regressions, loose ends, ideas, questions: `t9 add bug|regression|revisit|idea|question "…"`.
- Finished or blocked: `t9 done ID -n "…"`, `t9 status ID blocked -n "…"`.
- Before stopping: record any decisions not yet recorded, then `t9 handoff "where I stopped; what is next; open risks"`.
- Look before adding (`t9 ls --tree`, `t9 search "…"`), quote item ids in replies, and never let a failing `t9`
  command block the user's task.
